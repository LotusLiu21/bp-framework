# BP 叙事框架 — 案例参考

> 来源：BP 要素 PPT（14 页）  
> 用途：在教练过程中作为类比，帮助用户理解每个支柱应该怎么讲。

---

## 案例一：Coinbase — 抓住不可逆拐点（Timing）

### 为什么适合这个支柱

Coinbase 的“为什么是现在”非常典型。真正让 Coinbase 故事升级的，是机构基础设施开始成熟：它与 BlackRock 的 Aladdin 打通，让机构客户可以在既有投资管理工作流中直接接入比特币敞口。这说明故事不再只是“加密货币很大”，而是“制度化、合规化、机构化的拐点已经到来”。

### 一句话商业故事

> 加密不是突然变重要，而是当 BlackRock 这样的机构基础设施开始接入时，它就从边缘实验变成主流金融系统的一部分。

### 可以借鉴的结构

Timing 最好不要说“这是未来趋势”，而要说“以前做不成的三件事，现在同时成立了”。

Coinbase 讲的是：机构需求出现了、合规与托管能力成型了、传统金融工作流开始接入了。所以“现在”不是概念时点，而是结构窗口。

## 案例二：NVIDIA CUDA — 生态护城河（Moat）

### 为什么适合这个支柱

NVIDIA 真正的护城河，不只是 GPU 芯片性能，而是 CUDA 这一整套软件层和开发者生态。围绕它构建了 toolkit、库、调试工具、性能优化工具、Python 支持、CUDA-X 行业库等整套体系。这意味着竞争对手即使做出不错的硬件，也未必能复制开发者工作流、教育体系、工具链和框架兼容性。护城河之所以深，不在于“先发”，而在于它已经变成开发者的默认路径依赖。

### 一句话商业故事

> 我们卖的不是芯片，而是开发者已经离不开的计算平台。

### 可以借鉴的结构

讲 Moat 时，最好从“客户为什么很难迁移”入手。NVIDIA 不是靠一句“技术领先”建立护城河，而是让开发者从编程语言、库、框架到调试工具全部深度绑定。真正有力的护城河故事，都是“你知道别家存在，但你换过去的成本高得不值得”。

## 案例三：AWS — 从单点到平台（Scale）

### 为什么适合这个支柱

AWS 最经典的地方在于，它把一个内部效率问题，讲成了一个全球级平台机会。Amazon 早期发现，搭建和管理 IT 基础设施既昂贵又分散团队精力，于是把自己内部反复搭好的能力产品化，变成任何人都能调用的云服务。要让“哪怕宿舍里的学生”也能使用和最大公司一样强大的技术能力。这个故事天然具备 Scale：从 Amazon 自用，到创业公司，再到全球企业；每扩一层，边际复用能力都更强。

### 一句话商业故事

> 先解决自己的基础设施难题，再把它做成全世界都能调用的标准能力。

### 可以借鉴的结构

讲 Scale 的好故事，不是“市场很大”，而是“同一套能力可以跨无数场景复用，且复用成本越来越低”。AWS 的可借鉴点在于：从一个极窄、极痛的起点切入，但一开始就把底层能力设计成可以无限扩张的平台。

## 案例四：亚马逊与小米的飞轮（Scale / 生态扩张）

### 图 10：亚马逊的飞轮

**数据来源：西南证券**

飞轮核心：增长

驱动循环：

- 客户数 → 流量
- 流量 → 用户体验
- 用户体验 → 客户数

飞轮外层扩张：

- 电商平台 & Prime 会员（客户数、用户体验）
- Marketplace 第三方卖家平台（多样化选择）
- 全食 / Amazon Go（渠道可达、新零售）
- AWS-EC2 云服务（技术基础设施平台）

时间节点示例：

- 1995-2001：电商平台 & Prime 会员
- 2000-2005：Marketplace 第三方卖家平台
- 2007-2017：全食 / Amazon Go
- 2006-至今：AWS-EC2 云服务

### 小米的飞轮

飞轮核心：增长

驱动循环：

- 客户数 → 流量
- 流量 → 用户体验
- 用户体验 → 客户数

飞轮外层扩张：

- 智能手机（2011-2015，2965 亿）
- IoT 生态链 / 多样化选择（2014-2023，1375 亿）
- 互联网服务 / 流量变现（2016-2023，560 亿）
- 小米产业投资基金（2016-2023）
- 中国先发全球品牌 / 全球最大互联 IoT 平台 / X 万亿终局

### 可借鉴点

飞轮图不是装饰，而是 Scale 故事的可视化证据：同一套核心能力（客户获取、用户体验、流量变现）在不同阶段驱动不同业务层，形成非线性扩张。

## 如何在教练中使用这些案例

1. **Timing 薄弱时**：用 Coinbase 反问用户——“你的行业里，哪三件以前做不成的事，现在同时成立了？”
2. **Moat 被质疑时**：用 NVIDIA CUDA 反问用户——“客户换掉你的真实成本是什么？是技术、工具链、数据还是生态依赖？”
3. **Scale 讲不清时**：用 AWS 反问用户——“你的能力是不是从解决一个极窄问题开始，但底层架构天然可以跨场景复用？”
4. **生态扩张讲不清时**：用亚马逊 / 小米飞轮反问用户——“你的增长飞轮中，哪几个变量互相加速？每一层扩张是否共享同一套核心资产？”
